## 对本工作区的含义

1. **升级跨度真实存在**：rc.1 → 0.1.5-alpha.2 会一次引入 v2 + v3 两级格式迁移 + 跨进程写租约。我们自己的会话日志工具链需复核：`.tmp-audit-all.mts` 等修复脚本、chat-rail 投影读取、会话标题修补脚本。
2. **官方桌面端出现，SSiD 定位需重新评估**：`@deepseek-ai/dsh-desktop` 与思灵同为「Electron 壳 + DSH 内核」，官方方案还带独占 profile、自带 Node/pnpm、签名分片更新。SSiD 的差异化（插件全家桶、中文本地化、壳集成）需要重新论证。
3. **npm 通道已开**：`alpha` tag = `0.1.5-alpha.2`，可直接 `pnpm add @deepseek-ai/dsh@alpha` 试验，无需源码 checkout。
4. **侧边栏体系大改**：`ui-sidebar-files` / `ui-dockkit` / `ui-sidebar-right` 与第三方 better-sidebar 类插件存在重叠面，升级前需适配评估。
5. **工具集默认变化**：若某 profile 依赖 `str_replace_editor`，升级后需显式启用。
6. **subprocess 强化偏 Windows**：子窗口隐藏、PTY scope、containment 结算——与 SSiD 的 node-pty/子进程路径相关，升级后必须实测。

## 方法备忘（下次续写）

- 观察库：`DSHfork`（origin=官方主库，master 跟踪 origin/master）
- 更新流程：`git -C DSHfork fetch origin --tags` → `git log <上次tag>..origin/master` → 按主题聚类精读代表提交 → 追加新观察文档
- 口径校验：`git merge-base --is-ancestor <commit> <基线tag>` 确认提交是否真在基线内（release 分支 tip 常不含并行开发的提交）
- **新增包判定**：用 `git ls-tree -r -d --name-only <tag> -- packages apps` 做**目录级** Compare-Object；**不要用 `git diff --name-status`**——文件级 A 会把已有包里的新文件误判为"新包"
- 版本对比基线 tag 命名：`dsh-v0.1.x.y`；**当前最新 tag：`dsh-v0.1.5-alpha.2`**
- npm 查询：`https://registry.npmjs.org/-/package/@deepseek-ai/dsh/dist-tags`（轻量）；发布时间用 `https://registry.npmjs.org/@deepseek-ai/dsh` 的 `time` 字段
