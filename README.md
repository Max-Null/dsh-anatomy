# dsh-anatomy

对上游 **[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)** 的**解剖**：把它的内部构造拆开看——
它凭什么这么判断、门禁怎么编排、版本与版本之间差在哪。

> **为什么独立成库**：这批内容**跟着上游走**。DSH 升级一次，结论就可能失效、需要重读；
> 而它的读者也不限于 SSiD——任何想搞清 DSH 工程判断的人都能用。混在应用仓库的决策记录里，
> 两者的**更新节奏**会互相拖累。

## 目录

| 目录 | 内容 | 更新触发 |
|---|---|---|
| `版本对比/` | 逐版对比（`0.1.x vs 0.y.z`）：新增包、破坏性变更、能力变化 | **每个内核版本发布后** |
| `决策精读/` | 读官方 `.agents/notes/` 决策记录，提炼「他们凭什么这么判断」 | 官方新增决策记录后 |
| `工程范式/` | 官方 `scripts/verify-*` 门禁与 `run-gates` 编排的拆解、工程方法论 | 官方工程结构变动后 |

## 当前基线

见 [`基线.md`](./基线.md)。**笔记的结论只在其标注的基线版本上成立** ——
引用本库内容时，先确认基线是否仍匹配。

## 与其他库的关系

- **[dsh-skills](https://github.com/Max-Null/dsh-skills)** —— 本库是「读上游得出判断」，那个库是「按判断产出可安装的 skill」
- **[seek-soul-in-darkness](https://github.com/Max-Null/seek-soul-in-darkness)** —— SSiD 自身的决策记录留在那边；本库只放**对上游的观察**
