# rc.1 导航条（会话侧边栏）加载机制对比（2026-09-05）

> 背景：rc.1 对大会话加载做了新设计（投影缓存 + 窗口化惰性渲染，实测 195 万 token 会话 0.4s 打开）。
> 官方同期为侧边栏新增了自有的会话管理 UI（归档/移动/删除/分组）。本对比回答：官方机制是什么、
> 我们的导航条插件（dsh-session-manager 等）是否受影响、可借鉴什么。

## 1. 官方 rc.1 导航条机制（源码实证）

- **注册者**：`sidebar.workspaces` slot 由 `packages/client/ui-workspace` 提供（`client/navigation.ts` +
  `client/tree.ts` + `stores.ts`）；外层壳是 `ui-sidebar/SidebarRoot`（列几何/折叠/滚动条，纯壳）。
- **列表数据 = session 投影**，不是全量会话：
  - `SessionSummary` 字段：`blank` / `displayTitle` / `projectionValues`（如 schedule）/ 归档状态——
    **标题来自独立投影**（titleInput 的投影，先决标题不入搜索）。
  - `projectionValues` 是每个会话的第 n 投影行（有界）；列表不加载完整消息流。
  - 物理缓存：`$DSH_HOME/storages/session_projcache/sessions/<id>.json`（18.6MB 会话的投影缓存仅 1.17MB）。
- **搜索 = 有界投影合并**（"Bounded merged search projection" + refine-query 提示位）：搜索时也是
  有界投影，不会把全部会话拉到浏览器。
- **渲染 = 折叠组窗口化**：组折叠时不渲染行（"visible rows (empty while the group is folded)"）；
  组内只渲染可见顶层行；顺序由 Workspace 树排序派生（`ordered`）。
- **会话打开 = 窗口化惰性**：打开大会话只渲染可见窗口（0.4s 实测；α.4 全量载入 20s+ 翻车已根除）。

## 2. 我们的导航条插件：dsh-chat-rail（实证）

- **定位**：「画卷式消息导航栏」——会话面板右侧竖排导航，每条用户消息一个指示点，scroll-spy 跟随，
  hover 画卷展开、点击跳转任意历史消息；消息星标收藏 + 一键回填。**消息级导航**（非会话列表）。
- **数据流**（`src/client/index.tsx` 实证）：
  - **chatRail 投影**：`anchorSeq`/`messageId` 来自官方 **chatRail projection**（projectionValues.chatRail：
    每条用户消息一行 seq/time/text 轻量摘要——projcache row keys 已验证）——**不读全量消息流**。
  - **DOM 锚点收集**：指示点从 `[data-chat-anchor-key^="13:input-message"]`（**已渲染窗口内的消息行**）
    收集——**跟随官方窗口化渲染**（可见窗口 = 导航点），5xx 行实证。
  - 跳转**加载反馈**（spinner + 加载中，长会话跳转不卡死）。
  - 收藏为自建 `FAVORITES_API`（一次性请求，非列表遍历）。
- **大会话敏感度：低**——数据全在官方投影 + 窗口化 DOM 内，无全量枚举。

## 3. 机制对照（官方 TurnNavigator vs dsh-chat-rail，源码实证）

> 官方**有**消息级导航：`ui-chat/src/client/chat/TurnNavigator.tsx` + `turn-rail-items.ts`
> （turn-rail 预览层 #3414，rc.1 已含）。chat-rail 将其**自动隐藏**（aria-label 双文案锚点，README 兼容性段），
> 由 chat-rail 统一承担会话导航——装 chat-rail 时官方导航不显示（现在依旧生效，功能无冲突）。

| 维度 | 官方 TurnNavigator（新 DSH 机制） | dsh-chat-rail（旧 DSH 起家、逐版对接） |
|---|---|---|
| 大纲数据源 | **turnOutline 投影**（每 turn：turn/seq/prompt/response——全会话 turn 大纲，投影行轻量） | **chatRail 投影**（每条用户消息：seq/time/text/images——全用户消息摘要，**粒度更细**） |
| 窗口数据源 | loaded window items（React 快照 `TurnNavigationItem`：anchorKey+富预览） | chat nodes（`ChatSnapshot.nodes` 新平面 **alpha.2+**；legacy `session.chat.nodes` 旧平面兜底——**双平面**） |
| 融合层 | **`mergeTurnRailItems` 纯函数模块**（outline→unloaded(seq)、loaded→loaded(key)、双源合并、turn 升序——唯一汇聚点） | **组件内收集 + 投影兜底**（collectFromNodes 枚举节点；投影用于预览/图/跳转序号——无独立融合模块，语义隐性散布） |
| anchor 类型 | **判别联合** `{loaded:key} \| {unloaded:seq}`（跳转决策明确） | key 重建（id→`13:input-message<id>`）+ seq 分开散落 |
| 跳转 | unloaded → 按 seq loadThrough 翻页 → 滚到 key | `loadThrough(seq)`（alpha.3+）/ 旧内核逐页循环回退 —— **同构**，且兼容面更宽 |
| 内核依赖 | **仅新内核**（turnOutline/ChatSnapshot 缺则大纲缺席） | **新旧通吃**（双平面 + 回退——主动兼容 α.2→rc.1 全谱系） |
| 渲染范式 | React 组件（ChatView 内正式注册） | portal + 行内 DOM 注入 + MutationObserver（旧范式，但不依赖内核数据、稳定可用） |
| 导航杆覆盖 | **全量稳定**（投影大纲 = 全会话 turn 均有标记，未加载 turn 可先翻页再跳） | **窗口导向**（指示点 = 已加载节点；投影作跳转/预览兜底——未加载窗口消息无指示点，但可经收藏/跳转 API 到达） |

## 4. 可借鉴点（机制层，官方 → chat-rail）

1. **投影全量 + 窗口富数据的融合层（最重要）**：抽官方风格纯函数 `mergeRailMessages(chatRailProjection, nodes)`——
   chatRail 投影提供**全量指示点/序号**（未加载消息也有点、可先 loadThrough 再落位——对齐官方「未加载也能导航」），
   nodes 提供窗口富预览/锚点；判别联合 anchor（loaded:key | unloaded:seq）。收益：导航杆全量稳定
   （当前指示点随窗口翻页变化）、可单测、跳转决策明确。
2. **anchor 判别联合**：对齐官方类型（关键区分「已加载直滚」vs「未加载先翻页」）。
3. **turnOutline 借力（可选增强）**：会话级 turn 分组头（大会话指示点过多时按 turn 分组折叠）——
   turnOutline 投影现成（projcache turnOutline row 已验证）。
4. **保留双平面**（chat-rail 优势，官方只有新平面）：新平面为主、旧平面仅在缺新快照时兜底——不动。

## 4b. 可借鉴点（会话列表/管理增强时的通用契约，官方 → 第三方侧）

1. **列表只消费投影**：一律 `useSessions/useWorkspaces`（SessionListState/投影字段）——不要自建
   fetch 全量列表端点；新增导航面板（如追问树）的会话元数据取自投影（id/displayTitle/archived）。
2. **搜索走有界投影**：做列表内搜索/过滤时用官方 search-projection 语义（bounded + refine 提示），
   或在本地对已投影的可见行过滤（集合操作）——绝不拉全量。
3. **树渲染窗口化**：折叠组不渲染行（visible rows only），避免一次性渲染数百会话。
4. **标题信息一律 displayTitle**：不自己读会话文件取标题（官方投影已经含标题 + 独立性语义）。
5. **消息级导航同构 chat-rail 范式**（chat-rail 本身就是投影契约示例）：消费对应 projectionValues
   （chatRail 行 = 用户消息摘要）+ DOM 锚点收集已渲染窗口——大会话下自动轻量。
6. **操作端点保持单会话作用域**：/api 的一次性操作（归档/移动/preset 扫描）不携带列表载入。

## 5. 结论

- rc.1 大会话新设计（投影 + 窗口化）**已通过专项验证**（0.4s），SSiD 零适配。
- **导航条（dsh-chat-rail）与官方 TurnNavigator 同层同源**（chatRail/turnOutline 投影 + ChatSnapshot 节点
  窗口 + loadThrough 跳转——机制同构；差异：官方「投影全量导航杆 + 融合层纯函数 + 仅新内核」、chat-rail
  「窗口导向指示点 + 双平面兼容 + 旧范式渲染」——**屏蔽官方 TurnNavigator（aria 锚点）仍生效，功能无冲突**）。
- **机制层可借鉴**（§4）：①投影全量 + 窗口富数据融合层（导航杆全量稳定——当前指示点随窗口翻页变化）
  ②anchor 判别联合 ③turnOutline 借力做回合分组头（可选）④保留双平面（chat-rail 优势）。
- **会话列表相关第三方插件**（session-manager/sidebar-qa/better-sidebar）：已同源官方 hooks（或无关），
  按用户决策**本次不处理**（记录在 §2b，后续如需增强按 §4b 契约）。
- 待办：无新增。后续（自愿）可做「消息级导航增强」（如时间线/搜索跳转）——按 §4.5 chat-rail 范式。
